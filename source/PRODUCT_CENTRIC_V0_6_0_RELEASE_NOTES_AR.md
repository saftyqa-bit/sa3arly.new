# سعرلي 0.6.0 — قاعدة بيانات متمحورة حول المنتج

هذه النسخة تطبق التصميم الجديد فوق PostgreSQL الحالية بدون حذف الجداول أو
تغيير عقود الـAPI العامة الحالية.

## ما تمت إضافته

- `countries` و`currencies` لتوسعة سعرلي خارج مصر لاحقًا بدون قاعدة جديدة.
- شجرة `categories` موحدة، وجدول `brands` منظم.
- `product_models` كمنتج رئيسي، مع استمرار `product_variants` للون والسعة
  والمواصفات الدقيقة.
- ربط كل Variant بالمنتج والتصنيف والماركة والدولة والعملة.
- `data_review_queue` للمطابقات والبيانات التي تحتاج قرارًا بشريًا.
- `audit_log` لتسجيل التغييرات في المنتجات والنسخ والربط بالمتاجر.
- `catalog_products_v2` لعرض المنتج الرئيسي بدون تكرار أعداد العروض.
- `admin_data_quality_summary` لمؤشرات الجودة والتشغيل.
- API داخلي خاص بلوحة الإدارة.
- صفحة `/admin` محمية بقائمة بريدية ومصممة للعربية وRTL.

## الأمان والتوافق

- Migration `005` إضافية ولا تحذف بيانات الإنتاج.
- أسعار الكاش والتقسيط تظل في جداولها الحالية المستقلة.
- تاريخ الأسعار الحالي يظل مصدر التتبع التشغيلي؛ لا يتم نسخ كل تحديث آلي إلى
  `audit_log` حتى لا تتضخم القاعدة.
- لا تعرض صفحة الإدارة أي بيانات بدون بريد مسموح ومتغيرات Server-only.
- وضع المعاينة يعمل محليًا فقط ولا يعمل في Production.

## مسارات الإدارة الجديدة

```text
GET  /internal/admin/summary
GET  /internal/admin/review-queue
GET  /internal/admin/products
POST /internal/admin/review-queue/{review_id}/decision
```

كل هذه المسارات محمية بـ`X-Internal-Token`، والواجهة تتصل بها من السيرفر فقط.

## ترتيب التطبيق

1. نسخة احتياطية من Cloud SQL.
2. تشغيل خط الأساس `001_sa3arly_core_v2.sql` في نطاقات مستقلة، ثم نسخ بيانات
   `public` والتحقق منها قبل تحويل الاتصال.
3. نشر API 0.6.0.
4. ضبط متغيرات لوحة الإدارة ونشر الواجهة.
5. فتح `/admin` والتحقق من الأرقام وقائمة المراجعة.
6. عدم تفعيل أي حذف جماعي؛ جميع الرفضات تستخدم تعطيلًا منطقيًا في المرحلة
   التالية بعد اعتماد سير العمل.

## سكربت النشر

```bash
chmod +x DEPLOY_PRODUCT_CENTRIC_V0_6_0.sh
./DEPLOY_PRODUCT_CENTRIC_V0_6_0.sh
```

السكربت يحفظ حالات الـSchedulers والـQueues ويرجعها كما كانت، ويعيد توجيه
الترافيك إلى الـRevisions السابقة تلقائيًا عند فشل مرحلة بعد بدء القطع.
نشر صفحة `/admin` يتم من منصة الواجهة بعد ضبط متغيرات السيرفر المذكورة في
`sites-frontend-v13/.env.production.example`.
